# Phase 6.1: Video Marketing Copy Parity + Thumbnail Visual Selection Research

**Researched:** 2026-02-20
**Domain:** Marketing-copy schema parity plus visual thumbnail selection UX for Streamlit review workflow
**Confidence:** HIGH (stack/contracts), MEDIUM (thumbnail virality scoring heuristics)

## Summary

Phase 6.1 has two coupled deliverables that should be planned as one research-backed implementation wave with two execution tracks:
1. establish full-platform, LLM-generated marketing-copy coverage (including `spotify_video` and `apple_video`) with explicit quality constraints, and
2. upgrade thumbnail review from text-only cards to visual frame selection with 1-3 picks plus one explicit viral-style recommendation.

For marketing parity, the current gap is architectural, not UI-only: keys must exist in provider prompt schema, Pydantic model schema, render marketing document sections, and Streamlit marketing editor platform lists. If any layer is skipped, data is silently dropped or never rendered. The fix should be expanded from video-key parity into full-matrix parity: `youtube`, `spotify`, `spotify_video`, `apple`, `apple_video`, `tiktok`, `instagram`, `linkedin`, `twitter`, `facebook`.

For marketing quality, schema parity alone is insufficient. The prompt contract should enforce LLM-authored copy quality constraints (high-impact/viral angle without spammy clickbait, platform-tailored structure, and professional voice), and should consume trend context from the existing research pipeline when available (`analysis/research.json`, `analysis/viral_signals.json`).

For thumbnail UX, use the existing stage architecture and avoid adding a new pipeline stage. The recommended pattern is analyze-stage frame extraction (cached to disk) plus Streamlit image grid rendering from file paths, with ranked multi-select state (`selected_thumbnails`) and backward-compatible mirroring to legacy `selected_thumbnail`.

**Primary recommendation:** Implement Phase 6.1 as two additive tracks on current architecture: (A) strict full-platform marketing contract + trend-aware LLM prompt wiring with regressions, (B) full thumbnail MVP implementation (analyze-time image materialization + Streamlit visual multi-select contract (`1..3`) + AI-backed thumbnail `virality_score` with deterministic fallback scoring + render-time per-target compliance checks).
**MVP boundary lock:** enforce per-selected-platform thumbnail output constraints at render time (fail fast on unsatisfied spec), and defer explicit per-platform thumbnail assignment UX (different thumbnail per platform) to the immediate post-MVP increment.

**Research refresh (2026-02-20):**
- YouTube creator docs still show 100-character title limit and 5000-character description max, with guidance to keep descriptions unique/keyword-aligned.
- Spotify for Creators publishing docs still require title + description at publish time for video episodes; Spotify creator guidance emphasizes concise, keyword-forward episode descriptions.
- Apple Podcasts creator docs currently show episode metadata limits in Apple Podcasts Connect (episode name up to 150 chars; description up to 10,000 chars for Connect-managed episodes).
- YouTube custom thumbnail constraints remain explicit in official docs: 1280x720 recommended, minimum width 640, aspect ratio 16:9, supported image formats include JPG/GIF/PNG/BMP, and max upload size is 2 MB.
- Spotify for Creators thumbnail docs explicitly require 16:9 and list 1920x1080 as suggested resolution (article metadata `updatedAt: 2024-11-13T19:30:30Z`); no stricter official file-size/format limits were found in that page.
- Apple Episode Art docs remain explicit: square artwork, preferred 3000x3000 (RSS accepts 1400x1400..3000x3000), PNG/JPG, and no transparency/alpha.
- FFmpeg download/release docs list 8.0.1 as latest stable in the 8.0 release branch (released 2025-11-20), and ffmpeg-doc confirms `-ss` seek + `-frames:v 1` + accurate-seek behavior for precise frame extraction.

### Pattern 1: Contract-First Full-Platform Marketing + LLM Quality Gate
**What:** Treat marketing platform keys and quality instructions as a first-class provider/model contract, not optional UI text.
**When to use:** Any change to provider output shape, prompt quality requirements, or platform coverage.
**Example:**
```python
# Source: existing project contract flow (providers -> AnalysisResult -> artifacts/UI)
class MarketingCopy(BaseModel):
    youtube: PlatformMarketing = Field(default_factory=PlatformMarketing)
    spotify: PlatformMarketing = Field(default_factory=PlatformMarketing)
    spotify_video: PlatformMarketing = Field(default_factory=PlatformMarketing)
    apple: PlatformMarketing = Field(default_factory=PlatformMarketing)
    apple_video: PlatformMarketing = Field(default_factory=PlatformMarketing)
    tiktok: PlatformMarketing = Field(default_factory=PlatformMarketing)
    instagram: PlatformMarketing = Field(default_factory=PlatformMarketing)
    linkedin: PlatformMarketing = Field(default_factory=PlatformMarketing)
    twitter: PlatformMarketing = Field(default_factory=PlatformMarketing)
    facebook: PlatformMarketing = Field(default_factory=PlatformMarketing)
```

Prompt contract addition:
- Generate marketing copy for every key above.
- Use high-level viral framing with professional tone (no clickbait spam).
- Use trend/research keywords when available in prompt context.

### Pattern 2: Analyze-Stage Thumbnail Materialization
**What:** Extract thumbnail candidate images immediately after AI analysis so review UI reads static files.
**When to use:** Any candidate list with known timestamps and available proxy media.
**Example:**
```bash
# Precise extraction per timestamp (accuracy first; small candidate count keeps cost acceptable)
ffmpeg -y -hide_banner -loglevel error \
  -i intermediate/proxy.mp4 \
  -ss 00:12.345 \
  -frames:v 1 -q:v 2 \
  intermediate/thumbnails/candidate_00.jpg
```

### Pattern 3: Streamlit Hybrid Card (Native Image + Markdown Metadata)
**What:** Render image with `st.image(...)` and metadata/actions below it in the same column.
**When to use:** Any visual thumbnail grid in review UI.
**Example:**
```python
cols = st.columns(3, gap="small")
for idx, candidate in enumerate(candidates):
    with cols[idx % 3]:
        st.image(candidate["path"], width="stretch")
        st.caption(candidate["timestamp"])
        st.markdown(f"**Overlay:** {candidate['suggested_text_overlay']}")
        selected = idx in st.session_state.selected_thumbnails
        if st.button("Select", key=f"thumb-{idx}", type="primary" if selected else "secondary"):
            toggle_ranked_selection(idx)  # keeps max 3 and preserves order
```

### Pattern 4: Ranked Multi-Select with Backward Compatibility
**What:** Store ordered picks (`selected_thumbnails`) where first is primary and next two are alternates; keep legacy mirror field.
**When to use:** Thumbnail A/B or fallback-ready publishing workflow.
**Example:**
```python
class ReviewDecisions(BaseModel):
    selected_thumbnails: list[int] = Field(default_factory=list)  # ordered, unique, 1..3
    selected_thumbnail: int | None = None  # legacy mirror of selected_thumbnails[0]
```

### Pattern 5: AI-First Thumbnail Virality Scoring with Deterministic Fallback
**What:** Request `virality_score` and `viral_style` from provider; fallback to heuristic score if absent.
**When to use:** Provider drift, partial payloads, or transcript-only fallback providers.
**Example:**
```python
# Heuristic fallback (0-10) if provider omits virality score
score = 0
score += 3 if has_emotion_signal(desc, emotion) else 0
score += 2 if has_human_subject(desc) else 0
score += 2 if indicates_peak_action(desc) else 0
score += 2 if has_clear_overlay_headroom(desc) else 0
score += 1 if confidence_score and confidence_score >= 0.7 else 0
```

### Pattern 6: MVP Spec Enforcement + Deferred Platform Mapping
**What:** Use one primary thumbnail selection path for MVP, but always generate/validate thumbnails against each selected export target's constraints; reserve per-platform thumbnail mapping for follow-on work.
**When to use:** Phase 6.1 implementation planning and acceptance criteria.
**Example:**
```text
MVP now:
- selected targets = youtube, spotify_video, apple_video
- enforce each target's thumbnail constraints during render/export
- fail-fast if any selected target cannot be satisfied

Deferred next:
- platform-specific assignment (e.g., youtube->A, spotify_video->B, apple_video->C)
```

### Anti-Patterns to Avoid
- **Prompt-only marketing fixes:** keys still drop at model validation if schema fields are missing.
- **Video-only marketing fixes:** adding only `spotify_video`/`apple_video` while leaving other platform keys drifting keeps partial/fragile copy coverage.
- **Trend-blind copy generation:** ignoring available `research.json`/`viral_signals.json` context produces weaker marketing outputs for fast-moving topics.
- **UI-only thumbnail extraction:** long FFmpeg calls block reruns and degrade operator experience.
- **Replacing `selected_thumbnail` without migration:** breaks old `review_state.json` payloads.
- **Sorting thumbnails without preserving analysis index:** selections map to wrong frame on save/export.
- **Assuming Spotify/Apple have native thumbnail A/B features:** official docs reviewed do not document that.

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Frame extraction | Custom OpenCV frame seek pipeline | FFmpeg `-ss` + `-frames:v 1` | Mature decoder behavior and existing project wrapper |
| Visual card rendering | HTML-only image/card composition hacks | Native `st.image` + `st.columns` + standard widgets | Streamlit rerun/state model works predictably with native components |
| Thumbnail A/B engine | Custom experiment winner logic | YouTube Studio Test & Compare (where applicable) | Platform-native metric is watch-time share and already integrated by YouTube |
| Platform publish automation | Direct upload hand-rolled for Spotify/Apple | Keep artifact-first workflow boundary | Current provider workflows are dashboard/provider mediated |
| Schema migrations | One-off JSON rewrite scripts | Additive model fields + normalization shims at load/write | Safer backward compatibility with existing jobs |

**Key insight:** Phase 6.1 value comes from contract correctness + trend-aware LLM prompt quality + pragmatic UX improvements, not from introducing new subsystems.

## Common Pitfalls

### Pitfall 1: Silent Key Loss in Marketing Payload
**What goes wrong:** Platform keys appear in provider output but disappear from artifacts/UI, or only a subset of platforms receives usable copy.
**Why it happens:** Pydantic model/prompt/render/UI drift out of sync, often fixing only one or two keys.
**How to avoid:** Keep `MarketingCopy`, prompt schema, render sections, and UI platform list in one full-matrix change set with regression locks.
**Warning signs:** Keys present in raw provider response but absent in `analysis/analysis.json`, or missing sections in `output/marketing/copy.md`.

### Pitfall 2: UI Jank from On-Demand FFmpeg Extraction
**What goes wrong:** Thumbnail tab interaction stalls or appears frozen.
**Why it happens:** Streamlit rerun executes extraction on each interaction without persisted cache.
**How to avoid:** Materialize thumbnail images in analyze stage and load via file paths in review.
**Warning signs:** Noticeable pauses when switching tabs or selecting thumbnails.

### Pitfall 3: Selection Index Drift
**What goes wrong:** Saved selection points to different candidate than user intended.
**Why it happens:** Display sorting/ranking changes index order without stable source index.
**How to avoid:** Persist both `analysis_index` and display rank; always save source index list.
**Warning signs:** Manifest `is_selected` does not match UI-selected card after rerender.

### Pitfall 4: Backward Compatibility Break in Review State
**What goes wrong:** Existing jobs fail to load or lose selection when schema changes.
**Why it happens:** Replacing scalar `selected_thumbnail` abruptly.
**How to avoid:** Keep `selected_thumbnail` as legacy field and hydrate `selected_thumbnails` on load.
**Warning signs:** Validation errors or empty selection on old jobs with prior review state.

### Pitfall 5: Overstating Virality Confidence
**What goes wrong:** UI claims "viral" for weak candidates.
**Why it happens:** Uncalibrated heuristics or missing provider score fallback policy.
**How to avoid:** Use explicit confidence/source labels (`provider` vs `heuristic`) and require at least one forced recommendation only when candidates exist.
**Warning signs:** Frequent mismatch between selected viral pick and human reviewer preference.

### 3) Ordered Multi-Select Helper
```python
def toggle_ranked(selection: list[int], idx: int, max_items: int = 3) -> list[int]:
    if idx in selection:
        return [item for item in selection if item != idx]
    return (selection + [idx])[:max_items]
```

### 4) Backward-Compatible Review State Normalization
```python
def normalize_thumbnail_selection(decisions: ReviewDecisions) -> ReviewDecisions:
    if not decisions.selected_thumbnails and decisions.selected_thumbnail is not None:
        decisions.selected_thumbnails = [decisions.selected_thumbnail]
    decisions.selected_thumbnails = list(dict.fromkeys(decisions.selected_thumbnails))[:3]
    decisions.selected_thumbnail = decisions.selected_thumbnails[0] if decisions.selected_thumbnails else None
    return decisions
```

- Using only `use_container_width` / `use_column_width` for `st.image`: both documented as deprecated in current Streamlit docs.
- Assuming thumbnail experiments are portable across all podcast platforms: official docs reviewed support YouTube testing; Spotify/Apple docs reviewed do not document equivalent native A/B thumbnail testing.

## Open Questions

1. **Where to store analyze-time thumbnails: `intermediate/thumbnails` vs `analysis/thumbnails`?**
   - What we know: `intermediate/proxy.mp4` is the source and review reads before render.
   - What's unclear: preferred artifact boundary for cleanup semantics.
   - Recommendation: use `intermediate/thumbnails` (close to proxy source) and keep render outputs in `output/thumbnails`.

2. **How strict should viral badge threshold be?**
   - What we know: providers may return uneven scoring quality; fallback heuristic is approximate.
   - What's unclear: target precision/recall for "viral-style" label in this product context.
   - Recommendation: always mark top-scoring candidate as recommended, and include `viral_score_source` for transparent operator judgment.

3. **Should selected alternates be copied or symlinked to canonical names?**
   - What we know: cross-platform filesystem behavior differs, especially on Windows.
   - What's unclear: deployment target constraints for symlink creation.
   - Recommendation: copy files (not symlink) for deterministic cross-platform behavior.
