  <name>Task 1: Migrate CI to --onedir + update tauri.conf.json + capabilities + prepare-sidecars + build.rs</name>
  <files>.github/workflows/desktop-release.yml, desktop/src-tauri/tauri.conf.json, desktop/src-tauri/capabilities/default.json, desktop/src-tauri/build.rs, desktop/scripts/prepare-sidecars.mjs</files>
  <action>
    1. **CI workflow** (`.github/workflows/desktop-release.yml`):
       - Change `--onefile` to `--onedir` in the PyInstaller build step. The `--console` and `--hidden-import` flags stay the same.
       - In the "Rename to target-triple convention" step, copy the ENTIRE `dist/podcast-backend/` output directory (not just the binary):
         ```
         mkdir -p backend-dist
         cp -r dist/podcast-backend backend-dist/podcast-backend-${{ matrix.target }}
         ```
         This preserves both the main binary AND the `_internal/` Python dependency tree that --onedir creates alongside it.
       - Update the upload step path accordingly to `backend-dist/` so the entire directory is uploaded as the artifact.
       - In the `build-desktop` job's "Download backend artifact" step: the download path stays `desktop/src-tauri/binaries/`.
       - In the `build-desktop` job's "Prepare sidecar binaries" step: update `BACKEND_BIN` env to point to the main binary inside the downloaded directory:
         `src-tauri/binaries/podcast-backend-${{ matrix.settings.target }}/podcast-backend${{ matrix.settings.ext }}`

    2. **tauri.conf.json** (`desktop/src-tauri/tauri.conf.json`):
       - Update `app.windows[0].width` to `1440`
       - Update `app.windows[0].height` to `900`
       - Add `"minWidth": 1024` and `"minHeight": 700` to the window config
       - Update CSP to also allow blob:, data:, and tauri://localhost for wavesurfer.js audio and convertFileSrc:
         `"csp": "default-src 'self'; connect-src 'self' http://127.0.0.1:8787; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' blob: tauri://localhost"`
       - **Fix externalBin to reference the binary inside the directory**: Tauri appends `{target-triple}{ext}` to the last path component of each externalBin entry. Change to:
         ```json
         "externalBin": ["binaries/podcast-backend/podcast-backend", "binaries/ffmpeg", "binaries/ffprobe"]
         ```
         This means Tauri looks for `binaries/podcast-backend/podcast-backend-{triple}{ext}` and the `_internal/` directory lives alongside it as `binaries/podcast-backend/_internal/`.
       - **Add bundle.resources** to include the entire `_internal/` directory so it is copied into the production app bundle:
         ```json
         "bundle": {
           "resources": ["binaries/podcast-backend/_internal/**/*"]
         }
         ```
         Add this as a sibling key to the existing `bundle` section (or create it if absent). This is required because Tauri's `externalBin` only bundles single files — the `_internal/` directory is silently dropped without this resources entry.

    3. **capabilities/default.json** (`desktop/src-tauri/capabilities/default.json`):
       - Add `"core:window:allow-set-title"` to permissions array
       - Add `"core:webview:allow-print"` to permissions array (for future use)
       - Add drag-drop event permission: The Tauri v2 webview drag-drop API (`getCurrentWebview().onDragDropEvent()`) works through the `core:webview:default` permission which is included via `core:default`. Verify `core:default` is already present (it is). No additional permission needed for drag-drop in Tauri v2.

    4. **prepare-sidecars.mjs** (`desktop/scripts/prepare-sidecars.mjs`):
       - This script handles sidecar binary preparation. With --onedir, the backend sidecar is a directory containing the main binary at `podcast-backend{ext}` plus `_internal/` with all Python dependencies.
       - Update the podcast-backend sidecar handling to copy the entire --onedir output directory:
         - The `BACKEND_BIN` env var now points to the main binary inside the directory (e.g. `src-tauri/binaries/podcast-backend-x86_64-unknown-linux-gnu/podcast-backend`).
         - Detect that the binary resides inside a directory by checking if its parent directory contains an `_internal/` subdirectory.
         - If so, copy the entire parent directory to `binaries/podcast-backend-{triple}/` (this gives Tauri the structure it expects: `binaries/podcast-backend-{triple}/podcast-backend-{triple}{ext}` plus `binaries/podcast-backend-{triple}/_internal/`).
         - The binary itself must be renamed to include the triple suffix (e.g. `podcast-backend-x86_64-unknown-linux-gnu`) to match Tauri's externalBin resolution. Rename it inside the copied directory.
         - The `_internal/` directory does NOT need renaming — it stays as `_internal/`.
         - For ffmpeg and ffprobe: continue using single-file copy logic (unchanged — these are pre-compiled single-file binaries, not --onedir outputs).
         - If `BACKEND_BIN` points to a file without a sibling `_internal/` directory: fall back to original single-file copy logic (backward compatible for local builds that used --onefile).

    5. **build.rs** (`desktop/src-tauri/build.rs`):
       - If `build.rs` contains a validation check for `binaries/podcast-backend-{triple}{ext}` as a single file path, update it to check for the binary inside the directory: `binaries/podcast-backend/podcast-backend-{triple}{ext}`.
       - Note: `SKIP_SIDECAR_CHECK=1` is used in CI (so this check only runs in local dev). Update the path pattern to match the new directory-based layout so local dev validation still passes.
       - If `build.rs` does not contain such a check, leave it unchanged.
  </action>

    4. **main.tsx** — Wrap App in QueryClientProvider:
       - Add imports: `import { QueryClient, QueryClientProvider } from "@tanstack/react-query";`
       - Create QueryClient instance OUTSIDE the render: `const queryClient = new QueryClient({ defaultOptions: { queries: { staleTime: 5000, refetchInterval: 5000 } } });`
       - Wrap `<App />` in `<QueryClientProvider client={queryClient}>`:
         ```tsx
         ReactDOM.createRoot(document.getElementById("root") as HTMLElement).render(
           <React.StrictMode>
             <QueryClientProvider client={queryClient}>
               <App />
             </QueryClientProvider>
           </React.StrictMode>,
         );
         ```

    5. **shadcn/ui init** — Run `npx shadcn@latest init` from the desktop directory:
       - This creates `components.json` and sets up the shadcn/ui path aliases
       - When prompted: style=default, base color=slate, CSS variables=yes
       - Or run non-interactively: `npx shadcn@latest init -d` (uses defaults)
       - After init, install commonly needed components: `npx shadcn@latest add button card tabs progress badge separator scroll-area`
       - Update `tsconfig.json` to add path alias if shadcn requires it: add `"paths": { "@/*": ["./src/*"] }` to compilerOptions and set `"baseUrl": "."`

    6. Verify the build compiles: `cd desktop && pnpm build` should succeed (tsc + vite build).
