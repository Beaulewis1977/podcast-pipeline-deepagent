**Step A — Create FillerTriageResult model** at `src/podcast_pipeline/models/triage.py`:

```python
from datetime import UTC, datetime
from pydantic import BaseModel, Field

class FillerTriageResult(BaseModel):
    """LLM verdict for one hedge filler."""
    filler_index: int = Field(ge=0)
    word: str
    category: str
    safe_to_remove: bool = False
    reason: str = ""
    llm_model: str = ""
    triaged_at: str = Field(default_factory=lambda: datetime.now(UTC).isoformat())
```

**Step B — Add `_triage_fillers()` to AnalyzeStage** in `src/podcast_pipeline/stages/analyze.py`:

1. Add a `_triage_fillers(self, job_dir: Path) -> list[FillerTriageResult]` method.
2. Load `transcribe/filler_cuts.json` from job_dir. Deserialize each entry as a dict (not necessarily FillerCut — be tolerant of both old and new formats). For each filler, check:
   - `category == "hedge"` AND `protected != True` → candidate for triage.
   - All other fillers are skipped (disfluencies auto-remove, protected keep, custom = operator choice).
3. If `self.config.fillers.enable_llm_triage` is False, return a list of `FillerTriageResult(safe_to_remove=False, reason="LLM triage disabled")` for all hedge candidates.
4. Build the LLM prompt for each hedge filler. Use this exact system/user template:

```
SYSTEM: You are an audio editor deciding whether a filler word can be safely removed.
USER:
Transcript excerpt: "{context_before} [{WORD}] {context_after}"
Filler word: "{word}"
Pause before: {pause_before_ms:.0f}ms  Pause after: {pause_after_ms:.0f}ms

Can this filler be SAFELY removed without changing the meaning, tone, or rhetorical
intent of the sentence? Removing it is safe if it is purely a verbal tick with no
expressive or semantic function.

Reply with exactly:
SAFE or REVIEW
reason: <one sentence>
```

5. Batch fillers into groups of max 20. For each batch, send a single LLM call with all prompts concatenated (separated by `---\n`). Use the OpenAI provider pattern already in the project (check if `self.config.api_keys.openai` is set; if not, skip triage with reason "No OpenAI API key configured").
6. Parse each response: look for "SAFE" or "REVIEW" on a line, then "reason: ..." on the next line. If parsing fails for a filler, default to `safe_to_remove=False, reason="Parse error: ..."`.
7. Write results to `analysis/filler_triage.json` as a JSON array of serialized FillerTriageResult objects.
8. Call `_triage_fillers()` at the end of the `run()` method, after existing analysis work completes. Log start/end with structlog.

IMPORTANT: The `llm_triage_model` field in FillerConfig defaults to `"gpt-4o-mini"` — this is NOT deprecated per research doc (Correction 5). Use the OpenAI client with this model. If the project does not yet have an OpenAI client, create a minimal one using the `openai` package (already in project deps) with the API key from `config.api_keys.openai`.

IMPORTANT: If filler_cuts.json doesn't exist or has no hedge fillers, write an empty array `[]` to filler_triage.json and return early.
