# Specification: Automated Branding, Captions, and Multi-Track Sync (V2)

**Status:** Draft / Revised
**Estimated Phase:** Phase 9 (Post-Intelligent Cut Quality)
**Goal:** Transform the pipeline from a "Cutter" into a "Fully Branded Production Suite" with automated typography, watermarking, and perfect multi-track synchronization—while strictly avoiding over-engineering.

---

## 🎯 Summary of Changes from V1 (The "Don't Over-Engineer" Pass)

1.  **Removed "Agentic Media Orchestration":** LLMs will *not* dynamically write or chain FFmpeg filtergraphs. The pipeline will use deterministic Python scripts to apply Brand Kits safely and reliably.
2.  **Thumbnail Generation (Imagen 4 + Local "Nano"):** Upgraded API calls from Imagen 3 to **Imagen 4** (Google's latest 2026 model with perfect text rendering). Added an architecture for a fast, free local diffusion model ("Nano" style, e.g., FLUX.1 Schnell) as a fallback without compromising the main VRAM used by `faster-whisper`.
3.  **Audio Sync Bounds:** Bounded the cross-correlation algorithm to the first 30-60 seconds at an 8kHz downsample to prevent massive RAM/CPU spikes. Added a manual offset slider to the UI.
4.  **Dropped AV1 & Film Grain:** Removed AV1 hardware/software encoding targets. HEVC (H.265) 10-bit via NVENC is now the sole target for "Ultra" quality, significantly simplifying the codebase.
5.  **Claude & MCP Server Roles:**
    *   The **FFmpeg MCP Server** is now strictly a Developer Experience (DX) tool for interacting with Claude Code/Cursor during development. The production app will *not* depend on it.
    *   **Claude** is integrated alongside Gemini/Kimi but strictly for *Analysis/Review* (edit plans, marketing copy, thumbnail prompts), not for executing video edits.
6.  **Practical RIFE Guidance:** Explicitly constrained the use of RIFE (Phase 8) to short-form vertical exports (TikTok/Reels) to convert 30fps to 60fps. It will be disabled for long-form (YouTube/Spotify) to avoid bloated file sizes and render times.

## 1. Dynamic Branding Profiles (Brand Kits)

Instead of hardcoded values, the app will support **Branding Profiles**. This allows an operator to switch between "The Corporate Look," "The Viral Reel Look," or "The Podcast Classic" with one click.

### Profile Schema (`BrandingProfile`)

Each profile will be saved in a new `branding/` directory as a JSON/YAML file.

| Field | Description | Example |
| :--- | :--- | :--- |
| `profile_name` | Unique name for the kit | "Neon Viral" |
| `brand_voice` | **Creative Persona / Style Instructions** | "Bold, provocative, targeting Gen Z entrepreneurs." |
| `logo_path` | Path to permanent PNG/SVG watermark | `./branding/assets/logo_white.png` |
| `logo_placement` | Corner or coordinate | `top_right` or `x=10, y=10` |
| `logo_opacity` | Visibility level | `0.8` |
| `font_path` | Path to custom `.ttf` or `.otf` | `./branding/fonts/Montserrat-Bold.ttf` |
| `caption_style` | Mapping of text properties | `color: #FFFFFF, size: 48, shadow: true` |
| `highlight_color` | Color for the "active" word in captions | `#FFFF00` (Yellow) |
| `bg_padding` | Vertical offset for mobile-safe zones | `15%` (Avoids TikTok UI) |
| `thumbnail_border` | Hex color and width for frames | `#00FF00, 20px` (YouTube style) |

### 1.1 The "Master Persona" Injection

To ensure the AI (Gemini/Claude) understands your specific taste, the `brand_voice` field will be injected as a **System Instruction** during the `Analyze` stage.

*   **Marketing Copy**: The AI will use your instructions to decide between "Funny/Witty," "Academic/Professional," or "Aggressive/Viral" tones for titles and descriptions.
*   **Thumbnail Prompts**: If you tell the AI you like *"Minimalist, high-key photography,"* it will ensure all Imagen 4 prompts follow that aesthetic rather than generating random styles.
*   **Clip Selection**: The AI will look for moments that match your persona.

### 1.2 Per-Platform Branding Registry

To maintain a consistent but tailored look across apps, the `BrandingProfile` can include **Platform Overrides**. When you select your export targets (e.g., YouTube + TikTok), the app automatically switches to the correct "Look Kit" for each file.

**Automatic Routing**: The Render stage will look for a key matching the platform name (e.g., `youtube: overrides`) in your profile. If it doesn't find one, it falls back to your "Master Look."

## 2. Automated Caption Engine (The "Viral" Look)

This feature leverages the word-level timestamps already generated by the `Transcribe` stage.

### Technical Implementation: ASS (Advanced Substation Alpha)

While `SRT` is simple, we will use **ASS** for rendering because it supports:
*   **Per-word coloring**: Highlighting the active word as it's spoken.
*   **Fixed positioning**: Ensuring text stays inside "social media safe zones."
*   **Animations**: Adding subtle pop-in or scale effects to words for high engagement.

### Workflow

1.  **Generate**: A helper script in `src/podcast_pipeline/utils/captions.py` converts the JSON transcript into a temporary `.ass` file.
2.  **Apply Styles**: The script injects the colors and fonts from the active **Branding Profile**.
3.  **Burn-In**: FFmpeg renders the captions directly onto the video using the `-vf subtitles=temp.ass` filter.

## 3. Multi-Track Sync & Clap Detection

Syncing high-quality external audio with camera video is a major pain point. We will automate this using **Bounded Audio Cross-Correlation**.

### The "Clap Detector" Heuristic

*   **Step A (Downsample & Bound)**: Convert the first 60 seconds of all tracks to a low resolution (8kHz mono) to prevent RAM/CPU spikes.
*   **Step B (Peak Alignment)**: Scan for a sudden, sharp volume peak (the "clap") and align the tracks roughly.
*   **Step C (Fine Sync)**: Use `scipy.signal.correlate` on the bounded 60-second chunks to find the exact sample offset.
*   **Step D (Application)**: Apply the calculated offset to the high-res original files.

### UI Fallback: The Manual Sync Slider
Because real-world audio is messy (no clap, background noise), automated sync will sometimes fail. The Streamlit UI will include a **Manual Offset Slider** (±X milliseconds). If the auto-sync is wrong, the operator simply slides it until it looks right, fulfilling the "don't over-engineer" philosophy of having an easy manual override.

## 4. Integrated Sound Sets (Stingers & Transitions)

The app will include a "Sound Library" folder. Operators can drop in WAV files used for specific "Production Events."

### Event Triggers (`config.yaml`)

*   **Intro Stinger**: Plays `intro_music.wav` at the very start of the render.
*   **Transition "Whoosh"**: Automatically plays `whoosh.wav` every time the video cuts between speakers or segments.
*   **Outro Theme**: Fades in `outro.wav` during the last 5 seconds.

### Automated Ducking
The pipeline will use FFmpeg's `sidechaincompress` to automatically duck the spoken podcast audio slightly when a sound effect plays. To avoid over-engineering, the attack/release parameters will be hardcoded to standard podcasting values so the audio doesn't "pump" weirdly between breaths.

## 5. AI Thumbnail Studio (Imagen 4 & "Nano" Local)

Seamlessly generate customized thumbnail art without leaving the app.

### Option 1: The Premium API (Imagen 4)
*   Google's **Imagen 4** (via Vertex AI/Gemini API) is the default for high-end thumbnails.
*   It offers perfect text rendering, meaning you can ask the AI to literally write the title of the podcast directly into the neon sign in the image.
*   **Workflow**: Gemini `Analyze` generates 3 prompts -> Imagen 4 API generates 4 images -> Images are saved locally to `output/thumbnails/` (cached so we don't recharge the API on pipeline reruns).

### Option 2: The Fast/Free Local Model (e.g., FLUX.1 Schnell)
*   For users with an RTX 5060 Ti who want free, local "viral" image generation.
*   **VRAM Strategy**: Running a fast 4-step diffusion model (like FLUX.1 Schnell or SD 3.5 Medium) locally requires careful memory management. The app will ensure `faster-whisper` is unloaded from VRAM *before* the diffusion model is loaded to prevent out-of-memory crashes.
*   **Workflow**: Gemini `Analyze` generates 3 prompts -> Local model is loaded into VRAM -> Generates images locally in <5 seconds -> Unloads from VRAM.

### Auto-Branding
All generated images (API or local) are automatically framed with your `thumbnail_border` and logo using FFmpeg image overlays before final review.

## 7. High-Fidelity Video Quality (The "Ultra" Export)

To compete with high-end production houses, the pipeline will support professional-grade encoding standards.

### HEVC 10-Bit Default (No AV1)
For podcast video (mostly talking-head, low motion), the codec choice is explicitly **HEVC (H.265) 10-bit** in an **MP4** container.
*   **Why HEVC?**: Hardware acceleration on an RTX 5060 Ti via NVENC is incredibly fast. At 8-12 Mbps for 1080p, it is visually lossless and halves the file size of H.264. Modern social platforms support it universally.
*   **Why No AV1?**: AV1 hardware/software routing is too complex for the marginal 15% bitrate savings on a talking-head video. Film grain synthesis is removed to prevent over-engineering. **HEVC 10-bit is the uncontested standard for this pipeline.**

### Practical RIFE Integration (Phase 8 Add-on)
*   **Usage**: RIFE frame interpolation will *only* be triggered for short-form vertical exports (TikTok/Reels/Shorts) to boost 30fps source footage to a viral-friendly 60fps.
*   **Constraint**: It will be explicitly skipped for long-form (YouTube/Spotify) exports. Interpolating a 2-hour podcast to 60fps wastes massive amounts of time and storage with zero benefit to the viewer.

## 8. FFmpeg Media Toolkit (Deterministic App Logic)

The app will use a shared **Python media toolkit library** (`ffmpeg_toolkit`). **crucially**: LLMs (Gemini/Claude) will *not* be given agentic control over these tools. The Render pipeline must remain 100% deterministic.

### 8.1 Architecture: Python First, API Second

```
                          +-------------------+
                          |  ffmpeg_toolkit    |  <-- Core Python library
                          |  (14 tools)        |  <-- Typed functions, validated I/O
                          +--------+----------+
                                   |
              +--------------------+--------------------+
              |                                         |
     +--------v-------+                        +--------v--------+
     | MCP Server     |                        | Direct Python   |
     | (Claude Code)  |                        | (Pipeline code) |
     | DEVELOPER USE  |                        | PRODUCTION USE  |
     +----------------+                        +-----------------+
```

### 8.2 Production Rendering (No Agentic Orchestration)
To avoid the "Known Hard Problem" of LLMs hallucinating FFmpeg parameters mid-render, **the app will not use Agentic Media Orchestration.**
Instead, the standard Python `pipeline.py` will read the `BrandingProfile.json` and execute a hardcoded, highly-tested sequence of `ffmpeg_toolkit` functions.

### 8.3 Claude & Multi-LLM Roles (Analysis Only)
Claude (via Anthropic SDK), Gemini, and Kimi are strictly responsible for the "Brain" work in the `Analyze` and `Review` stages:
*   Generating the JSON edit plan (where to cut).
*   Writing marketing copy.
*   Prompt generation for Imagen.

They will hand off the completed JSON plan to the Python rendering engine. The "Thinker" stays separate from the "Doer."

### 8.4 The FFmpeg MCP Server (Developer DX Only)
The `podcast_pipeline.mcp.ffmpeg_server` will be built, but **purely as a Developer Experience tool.** It allows you, the developer, to use Claude Code or Cursor in your terminal to rapidly test FFmpeg wrappers during development (e.g., asking Claude to quickly test a subtitle font rendering). *The production Streamlit app and CLI will never use the MCP server.*
