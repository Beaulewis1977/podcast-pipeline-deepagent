## 1. Dynamic Branding Profiles (Brand Kits)

Instead of hardcoded values, the app will support **Branding Profiles**. This allows an operator to switch between "The Corporate Look," "The Viral Reel Look," or "The Podcast Classic" with one click.

### Profile Schema (`BrandingProfile`)

Each profile will be saved in a new `branding/` directory as a JSON/YAML file.

| Field | Description | Example |
| :--- | :--- | :--- |
| `profile_name` | Unique name for the kit | "Neon Viral" |
| `brand_voice` | **Creative Persona / Style Instructions** | "Bold, provocative, targeting Gen Z entrepreneurs." |
| `logo_path` | Path to permanent PNG/SVG watermark | `./branding/assets/logo_white.png` |
| `logo_placement` | Corner or coordinate | `top_right` or `x=10, y=10` |
| `logo_opacity` | Visibility level | `0.8` |
| `font_path` | Path to custom `.ttf` or `.otf` | `./branding/fonts/Montserrat-Bold.ttf` |
| `caption_style` | Mapping of text properties | `color: #FFFFFF, size: 48, shadow: true` |
| `highlight_color` | Color for the "active" word in captions | `#FFFF00` (Yellow) |
| `bg_padding` | Vertical offset for mobile-safe zones | `15%` (Avoids TikTok UI) |
| `thumbnail_border` | Hex color and width for frames | `#00FF00, 20px` (YouTube style) |

### 1.1 The "Master Persona" Injection

To ensure the AI (Gemini) understands your specific taste, the `brand_voice` field will be injected as a **System Instruction** during the `Analyze` stage.

*   **Marketing Copy**: The AI will use your instructions to decide between "Funny/Witty," "Academic/Professional," or "Aggressive/Viral" tones for titles and descriptions.
*   **Thumbnail Prompts**: If you tell the AI you like *\"Minimalist, high-key photography,\"* it will ensure all image generation prompts follow that aesthetic rather than generating random styles. The `gemini-3-pro-image-preview` model will be used to review thumbnail composition and ensure brand alignment.
*   **Clip Selection**: The AI will look for moments that match your persona (e.g., if your voice is "Inspirational," it will prioritize clips with high emotional impact).

### 1.2 Per-Platform Branding Registry

To maintain a consistent but tailored look across apps, the `BrandingProfile` can include **Platform Overrides**. When you select your export targets (e.g., YouTube + TikTok), the app automatically switches to the correct "Look Kit" for each file.

| Platform | Typical Override | Logic |
| :--- | :--- | :--- |
| **YouTube** | High-contrast branding + Green Thumbnail Border | Horizontal focus, high-saturation |
| **TikTok/Reels** | Large "Viral" captions + 15% Bottom Padding | Vertical focus, UI safety avoidance |
| **LinkedIn** | Subtle watermark + Standard typography | Professional/Minimalist |
| **Shorts** | Combined Viral Style + Center Branding | Fast-paced, high engagement |

**Automatic Routing**: The Render stage will look for a key matching the platform name (e.g., `youtube: overrides`) in your profile. If it doesn't find one, it falls back to your "Master Look."

## 2. Automated Caption Engine (The "Viral" Look)

This feature leverages the word-level timestamps already generated by the `Transcribe` stage.

### Technical Implementation: ASS (Advanced Substation Alpha)

While `SRT` is simple, we will use **ASS** for rendering because it supports:

*   **Per-word coloring**: Highlighting the active word as it's spoken.
*   **Fixed positioning**: Ensuring text stays inside "social media safe zones."
*   **Animations**: Adding subtle pop-in or scale effects to words for high engagement.

### Workflow

1.  **Generate**: A helper script in `src/podcast_pipeline/utils/captions.py` converts the JSON transcript into a temporary `.ass` file.
2.  **Apply Styles**: The script injects the colors and fonts from the active **Branding Profile**.
3.  **Burn-In**: FFmpeg renders the captions directly onto the video using the `-vf subtitles=temp.ass` filter.

## 3. Multi-Track Sync & Clap Detection

Syncing high-quality external audio with camera video is a major pain point. We will automate this using **Audio Cross-Correlation**.

### The "Clap Detector" Heuristic

*   **Step A**: Scan the first 60 seconds of all tracks for a sudden, sharp volume peak (the "clap").
*   **Step B**: Align the tracks roughly around those peaks.
*   **Step C (The Pro Step)**: Use `scipy.signal.correlate` to compare the actual audio waveforms. This achieves **sample-perfect alignment** even if the clap was missed or messy.

### Benefits

*   **Zero Drift**: Detects if one recording device runs slightly slower than another and applies a `atempo` correction.
*   **Multi-Camera Ready**: Syncs multiple video angles to one master audio track.

## 4. Integrated Sound Sets (Stingers & Transitions)

The app will include a "Sound Library" folder. Operators can drop in WAV files used for specific "Production Events."

### Event Triggers

We will add a new `sound_events` section to the `config.yaml`:

*   **Intro Stinger**: Plays `intro_music.wav` at the very start of the render.
*   **Transition "Whoosh"**: Automatically plays `whoosh.wav` every time the video cuts between speakers or segments.
*   **Outro Theme**: Fades in `outro.wav` during the last 5 seconds.

### Automated Ducking

When a sound effect plays, the app will automatically **duck** (lower the volume) of the spoken podcast audio so the effect doesn't "drown out" the speaker.

Seamlessly generate customized thumbnail art without leaving the app. Using the new Gemini vision models, the AI will deeply analyze extracted visual frames to guide the creation process.

## 7. High-Fidelity Video Quality (The "Ultra" Export)

To compete with high-end production houses, the pipeline will support professional-grade encoding standards.

### 7.1 Codec Selection Strategy

For podcast video (mostly talking-head, low motion), the codec choice is:

| Codec | Quality/Bit | Speed (NVENC) | Speed (Software) | Platform Support | When to Use |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **HEVC (H.265)** | Excellent | Fast (RTX 5060 Ti) | Medium | Universal (2024+) | **Default for all exports** |
| **AV1** | Best (~15% smaller) | Experimental (Blackwell) | Very Slow | YouTube, Netflix | Film grain synthesis only |
| **H.264** | Good (baseline) | Very Fast | Fast | Everything | Legacy/fast fallback |

**Default: HEVC (H.265)** in an **MP4** container.
*   **Quality & Size**: Same visual quality as H.264 but at **50% of the file size**. At 8-12M bitrate for 1080p talking-head content, HEVC is visually lossless to the human eye.
*   **Universal Compatibility**: Modern social platforms (YouTube, TikTok, Instagram, LinkedIn) all natively support HEVC in an MP4 container.
*   **10-Bit Support**: Explicitly use the `main10` profile to enable smooth, banding-free color transitions.
*   **Hardware Acceleration**: RTX 5060 Ti NVENC encodes HEVC 10-bit in near-real-time. This is the sweet spot — maximum quality with fast encode.
*   **Compatibility Fallback**: H.264 will remain available as a "Legacy/Fast" toggle for older hardware that doesn't support hardware-accelerated HEVC.

**AV1 is optional, not default.** AV1's quality advantage (~15% bitrate savings) matters more for high-motion content (gaming, sports). For podcast video where the frame is mostly static, HEVC at a decent bitrate is already indistinguishable. AV1's main value here is its unique **film grain synthesis** feature. Blackwell NVENC AV1 support is still maturing as of early 2026 — use software `libsvtav1` until hardware encoding stabilizes.

### 7.2 Cinematic Enhancements
*   **10-Bit Color Depth**: Support for `yuv420p10le` pixel format to eliminate color banding in gradients and dark scenes.
*   **Film Grain Synthesis**: A unique AV1 feature that replaces digital noise with a pleasant cinematic texture while reducing bitrate requirements.
*   **Intelligent Denoising**: Using the `hqdn3d` and `nlmeans` filters to clean up low-light camera sensor noise before the final brand overlays are applied.

## 8. FFmpeg Media Toolkit & Multi-LLM Integration

The app will use a shared **Python media toolkit library** that all AI providers (Gemini, Kimi, Claude) access through their native tool-calling mechanisms, plus an optional **MCP server** for Claude Code interactive use.

### 8.1 Architecture: Library-First, Adapters on Top

```
                          +-------------------+
                          |  ffmpeg_toolkit    |  <-- Core Python library
                          |  (14 tools)        |  <-- Typed functions, validated I/O
                          +--------+----------+
                                   |
              +--------------------+--------------------+
              |                    |                    |
     +--------v-------+  +--------v--------+  +--------v--------+
     | MCP Server     |  | Gemini/Kimi     |  | Direct Python   |
     | (Claude Code)  |  | Tool Schemas    |  | (Pipeline code) |
     | mcp-server-    |  | (function-      |  | import & call   |
     | ffmpeg/        |  |  calling JSON)  |  | directly        |
     +----------------+  +-----------------+  +-----------------+
```

**Why this approach:**
*   **Single source of truth**: FFmpeg logic is written and tested once in the core library.
*   **No protocol lock-in**: Gemini and Kimi use their native function-calling; Claude uses MCP or direct calls. No translation layers.
*   **Pipeline reuse**: The existing `utils/ffmpeg.py` wrappers migrate into the toolkit. Render stage imports directly — zero overhead.
*   **Interactive bonus**: The MCP server lets Claude Code inspect and manipulate media files conversationally during development.

### 8.2 Claude as AI Provider (Anthropic Python SDK)

Claude joins Gemini and Kimi as a third AI provider for analysis and content generation. This requires the **Anthropic Python SDK** (`anthropic`), not the Agent SDK.

```python
# src/podcast_pipeline/providers/claude_provider.py
# Implements the existing AnalysisProvider protocol
class ClaudeProvider:
    async def analyze(self, video_path: Path, transcript: dict) -> AnalysisResult:
        # Uses anthropic SDK with tool_use for FFmpeg operations
        ...
```

*   **SDK**: `anthropic` (pip install anthropic)
*   **Auth**: API key via `ANTHROPIC_API_KEY` in `.env` (personal use — no commercial restrictions)
*   **Tool Use**: Claude's function-calling gives it access to the same FFmpeg toolkit functions that Gemini/Kimi use, defined as tool schemas in the provider layer.
*   **No Agent SDK needed**: The Agent SDK is for building standalone Claude agents. For an in-app provider, the standard SDK with tool use is correct.

### 8.3 Tool Inventory (14 Tools, 5 Groups)

Every tool follows the same pattern: typed Python function with Pydantic input/output models, exposed as both an MCP tool and an LLM function schema.

#### Group 1: Probe & Inspect (giving the AI "eyes")

| Tool | Purpose | Key Parameters | Returns |
| :--- | :--- | :--- | :--- |
| `probe_media` | Full metadata extraction | `path` | Codec, resolution, bitrate, duration, color space, HDR info, stream list |
| `extract_frame` | Screenshot at timestamp | `path`, `timestamp_s`, `output_path` | PNG image path (for AI visual verification of overlays/captions) |
| `detect_hardware_encoders` | List available GPU encoders | *(none)* | Available encoders: NVENC, QuickSync, VideoToolbox, software fallbacks |

**Supports Sections**: 8.1 (Visual Intelligence), 7.1 (codec detection)

#### Group 2: Encode & Transcode (the "Ultra" export)

| Tool | Purpose | Key Parameters | Returns |
| :--- | :--- | :--- | :--- |
| `transcode` | High-fidelity encoding | `input_path`, `output_path`, `codec` (h264/hevc/av1), `quality_preset` (fast/medium/slow), `bit_depth` (8/10), `film_grain` (0-50, AV1 only), `hw_accel` (auto/nvenc/none) | Output path, file size, encode time |
| `normalize_loudness` | EBU R128 per-platform | `input_path`, `output_path`, `target_lufs` (-14.0/-16.0), `true_peak_dbtp` | Output path, measured LUFS before/after |

**Supports Sections**: 7.1 (HEVC 10-bit), 7.2 (Film Grain Synthesis, AV1), existing platform export configs

**Adaptive Hardware Selection**: `hw_accel: auto` probes the system via `detect_hardware_encoders` and selects the best available:
1.  NVENC (RTX 5060 Ti) for HEVC/H.264
2.  Software libx265/libsvtav1 fallback for AV1 or when no GPU

#### Group 3: Filter & Overlay (branding and visual quality)

| Tool | Purpose | Key Parameters | Returns |
| :--- | :--- | :--- | :--- |
| `burn_captions` | Render ASS subtitles onto video | `video_path`, `ass_path`, `output_path`, `force_style` (optional override) | Output path |
| `overlay_image` | Logo/watermark compositing | `video_path`, `image_path`, `output_path`, `position` (top_right/bottom_left/x,y), `opacity` (0.0-1.0), `fade_in_s`, `fade_out_s`, `scale` | Output path |
| `apply_filtergraph` | Raw filtergraph execution (advanced) | `input_path`, `output_path`, `filtergraph` (string), `validate_first` (bool, default true) | Output path, applied filters list |
| `denoise` | Sensor noise cleanup | `input_path`, `output_path`, `method` (hqdn3d/nlmeans), `strength` (light/medium/heavy) | Output path |

**Supports Sections**: 1 (Branding Profiles — logo overlay), 2 (Caption Engine — ASS burn-in), 7.2 (Intelligent Denoising)

**Filtergraph Validation**: `apply_filtergraph` with `validate_first: true` runs a dry-run parse of the filtergraph string before execution, catching syntax errors and missing filter references without touching the output file.

#### Group 4: Edit & Assemble (production and sync)

| Tool | Purpose | Key Parameters | Returns |
| :--- | :--- | :--- | :--- |
| `trim_segment` | Frame-accurate cut | `input_path`, `output_path`, `start_s`, `end_s`, `copy_codec` (bool — no re-encode when possible) | Output path, actual start/end (snapped to keyframes if copy_codec) |
| `concat_segments` | Join clips with transitions | `segments` (list of paths), `output_path`, `transition` (none/crossfade/dissolve), `transition_duration_s` | Output path, total duration |
| `mix_audio` | Overlay music/stingers with ducking | `speech_path`, `music_path`, `output_path`, `music_volume_db`, `duck_enabled` (bool), `duck_threshold_db`, `duck_ratio`, `fade_in_s`, `fade_out_s` | Output path |
| `sync_tracks` | Cross-correlation alignment | `reference_path` (camera audio), `external_path` (mic audio), `output_path`, `search_window_s` (default 60) | Output path, detected offset (ms), drift correction applied (bool) |

**Supports Sections**: 3 (Multi-Track Sync — `sync_tracks`), 4 (Sound Sets — `mix_audio` with ducking), existing render stage (trim + concat)

**Sync Algorithm**: `sync_tracks` implements the three-step process from Section 3:
1.  Peak detection (clap finder) in first `search_window_s` seconds
2.  Coarse alignment via peak matching
3.  Fine alignment via `scipy.signal.correlate` for sample-perfect sync
4.  Optional `atempo` drift correction if clock skew detected

#### Group 5: Package & Deliver (multi-platform distribution)

| Tool | Purpose | Key Parameters | Returns |
| :--- | :--- | :--- | :--- |
| `package_hls` | VOD HLS with variant ladder | `input_path`, `output_dir`, `segment_duration` (default 6), `variants` (list of bitrate/resolution pairs) | Master playlist path, segment count, total size |

**Supports Sections**: Existing HLS config (apple_hls platform), Spotify Video/Apple Video mezzanine profiles

### 8.4 Agentic Media Orchestration

With all 14 tools available, any AI provider can execute multi-step media workflows autonomously:

**Example: "Apply the Neon Viral brand kit to the YouTube export"**

The AI agent (Gemini, Kimi, or Claude) would:
1.  `probe_media` — inspect the rendered video dimensions and codec
2.  `overlay_image` — add the logo at `top_right` with `opacity: 0.8` and 2s fade-in
3.  `burn_captions` — render the ASS file with Neon Viral highlight colors
4.  `transcode` — encode to HEVC 10-bit at YouTube's 8M bitrate target
5.  `extract_frame` — grab a thumbnail-timestamp screenshot for verification
6.  `normalize_loudness` — ensure -14.0 LUFS for YouTube

Each step is a single tool call. The AI decides the order and parameters based on the BrandingProfile and platform config.

### 8.5 Safety & Validation

*   **Input Validation**: All paths are resolved and checked for existence before FFmpeg runs. No shell injection — arguments are passed as lists, never interpolated strings.
*   **Filtergraph Pre-flight**: `apply_filtergraph` validates filter syntax before execution. Unknown filter names are rejected.
*   **Resource Guards**: Transcode operations check available disk space before starting. Timeout defaults prevent runaway encodes.
*   **Hardware Probing**: `detect_hardware_encoders` runs once at startup and caches results. If NVENC is requested but unavailable, the tool returns an error with a software fallback suggestion rather than silently failing.

### 8.6 MCP Server Configuration (Claude Code)

For interactive use via Claude Code, the toolkit is also exposed as an MCP server:

```jsonc
// ~/.claude/settings.json (or project .mcp.json)
{
  "mcpServers": {
    "ffmpeg-toolkit": {
      "command": "uv",
      "args": ["run", "python", "-m", "podcast_pipeline.mcp.ffmpeg_server"],
      "cwd": "/home/kngpnn/dev/podcast-pipeline-deepagent"
    }
  }
}
```

This lets Claude Code call `probe_media`, `extract_frame`, `overlay_image`, etc. directly during development sessions — useful for inspecting media files, testing filter chains, and verifying exports without leaving the CLI.

## 10. Build Strategy & Integration Risk Notes

### Build Order: Tools First, Orchestration Last

Each toolkit tool must be **standalone and tested** before wiring up LLM orchestration. Do not attempt multi-tool AI workflows until every individual tool is reliable.

**Recommended build sequence:**
1.  **Foundation tools** (probe, trim, concat, loudness) — mostly migrating existing `utils/ffmpeg.py` code. Low risk.
2.  **Encoding tools** (transcode with HEVC/AV1, hardware detection) — medium risk due to Blackwell NVENC edge cases.
3.  **Overlay tools** (captions, logo, denoise, filtergraph) — medium risk; ASS rendering requires template iteration per platform.
4.  **Production tools** (mix_audio, sync_tracks) — highest risk; real-world audio sync has many edge cases.
5.  **MCP server + LLM tool schemas** — mechanical wrapper work, do last.
6.  **LLM orchestration testing** — the real integration challenge. Test each provider (Gemini, Kimi, Claude) independently with progressively longer tool chains.

### Known Hard Problems

| Area | Why It's Hard | Mitigation |
| :--- | :--- | :--- |
| **Multi-step LLM tool use** | LLMs are inconsistent at chaining 5+ tool calls correctly. Parameters get hallucinated, steps get skipped. | Validate output after *every* tool call, not just the final result. Add guardrails that reject obviously wrong parameters. |
| **Audio sync (cross-correlation)** | Real recordings: no clap, late starts, background music, non-linear clock drift, mismatched sample rates. | Start with the happy path (clear clap in first 30s). Add fallback modes: manual offset input, waveform visualization in UI. |
| **ASS caption rendering** | Getting word-level highlights to look right across vertical (TikTok), horizontal (YouTube), and square (LinkedIn) from one transcript. | Build a template per aspect ratio. Don't try to auto-derive — hand-tune safe zones per platform. |
| **Blackwell NVENC** | RTX 5060 Ti (sm_120) is bleeding-edge. HEVC NVENC should work. 10-bit NVENC has per-generation quirks. AV1 NVENC may not be stable yet. | Probe hardware at startup. Always have software fallback. Test NVENC 10-bit early and log results. |
| **Pipeline state/recovery** | Phase 9 makes the pipeline a DAG, not a linear chain. When a mid-chain step fails, what's the recovery? | Each tool writes output to a unique path. Re-running a step overwrites only that step's output. Add a manifest file tracking which steps completed. |

### Success Criteria Per Phase

Each phase should be independently demoable before moving to the next:
*   **9.1**: `python -m podcast_pipeline.mcp.ffmpeg_server` starts, all 14 tools pass unit tests, MCP inspector can call each tool.
*   **9.2**: Claude provider passes the existing `AnalysisProvider` test suite alongside Gemini/Kimi.
*   **9.3**: A 1080p test video encodes to HEVC 10-bit via NVENC in under 2x real-time, with software AV1 fallback working.
*   **9.4-9.5**: A branded, captioned video renders from a test BrandingProfile + transcript JSON without manual intervention.
*   **9.6**: Two test audio tracks with a clap sync to within 10ms automatically.
*   **9.7**: A rendered video has intro music with auto-ducking that doesn't clip the speech.
*   **9.8-9.9**: Full pipeline demo: raw recording → synced → cut → branded → captioned → multi-platform export.
